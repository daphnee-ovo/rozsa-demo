## 实现与验证

`backend/internal/app/themes` 提供公开 `Store` 和 `Appearance` 接口，内部封装文件 store。内置 light/dark 定义与 CSS variables 对照 Rust 常量；自定义主题支持缺省字段继承、global/project 层级（项目同 ID 优先）、列表去重、只写 global、CSS 值/变量名/ID 校验和有路径的错误。`Appearance` 只通过 `SettingsOwner` 写入 T015 settings；选择主题先验证再写设置，其他支持的 appearance 更新也在 settings 写入成功后返回完整 snapshot。调用方拿到 snapshot 后负责宿主外观和 renderer 更新；Go themes 不读取系统明暗状态，也不执行 Electron/native 外观操作。

运行：

```text
gofmt -w backend/internal/app/themes/themes.go backend/internal/app/themes/themes_test.go
go -C backend test ./internal/app/themes/...
```

结果：`ok rozsa/backend/internal/app/themes 0.972s`。用例覆盖内置主题值、list/get/save、项目覆盖与 global 保存、partial JSON/default variables、解析与 validation 错误、not-found、UTF-8/读写失败、设置选择/更新的持久化顺序、无效选择不写文件，以及新 settings manager 重开后恢复选择。

失败路径有自动化检查：畸形/缺少 mode 的文件报 parse error；非法变量和无效 ID 报 validation error；缺失主题报 not-found；目录读取和写入目标冲突保留路径；未知主题选择失败时设置文件字节不变。Rust 将主题目录创建和文件写入 I/O 错误也包装为 `ThemeError::Read`，Go 保留该类别与路径，以维持当前错误映射。

本模块使用同步文件与 settings API，没有取消入口，因此 cancellation 不适用，未执行取消测试。恢复只验证持久化设置经新 manager 重开后的主题选择与定义；未验证 Electron/native 外观、系统主题切换 UI、Linux/Windows 实机或完整迁移验收。
