# M033 — Codex OAuth and model discovery

## Implemented behavior

- `backend/internal/model/oauth/codex` mirrors the current Rust authorization URL, PKCE, loopback callback at `/auth/callback`, manual redirect input, token exchange/refresh, expiration timestamp, and account claim extraction. The injected HTTP client and endpoint fields allow synthetic tests; no real authorization was performed.
- `backend/internal/app/auth/codex.go` stores and removes only `codex-oauth` at the explicitly supplied auth path. It supports an injected provider-change callback and optional model refresh callback. When a global models path is supplied, it refreshes the Codex catalog using the stored account ID.
- `backend/internal/model/modelsendpoint` requests `/wham/models` with `client_version`, bearer token, and account header. It observes the 24-hour cache, supports context cancellation, retains unknown root/provider configuration, and changes only `providers.codex-oauth`. Catalog entries require `supported_in_api: true`; visibility must be `list` when present.
- `devtools/sync-codex-model-client-version.sh` updates and checks both the Rust and Go compatibility constants. Explicit Rust `--target` fixture calls remain isolated unless `--go-target` is also supplied. Temporary generated files are contained under `tmp/`.

## Integration boundary

Production construction supplies `<global>/models/auth.json` and routes model discovery through the shared provider-scoped catalog callback. Project model configuration remains the higher-priority registry layer. The typed desktop login/cancel/logout path, browser request, directory updates and diagnostics are covered by [M092](M092.md). Real account authorization and native browser execution remain unverified.
