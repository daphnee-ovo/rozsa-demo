# M002：JSONL 只读打开与有效上下文恢复

进入日期：2026-10-13，Asia/Singapore。任务：TASK-T002。

## 保留的读取契约

| 来源行为 | Go Reader 行为 |
| --- | --- |
| 打开文件 | 只读打开；第一条非空行必须是合法 header。区分打开失败、读取/UTF-8 失败、invalid header、错误 header type 与空文件；malformed entry 可跳过，错误 header 不可跳过。 |
| index 与 leaf | 按文件顺序索引有效 entry；重复 ID 由后项替代；最后一条有效 entry（包括 metadata）选择 leaf，不按 timestamp 选择。 |
| active branch | 从 leaf 沿 `parentId` 回溯并反转为正序；缺失关联时停止。保留 metadata 与 compaction 前历史，不混入其他 branch。 |
| effective context | 仅按 active branch 上最新 compaction 的 `firstKeptEntryId` 裁剪；找不到 ID 时从开头保留。过滤 metadata，不合成 summary message。 |
| message 类型 | 保留 user、assistant、toolResult 及文本、thinking、image、toolCall、usage、cost、provider/API、response/error 等既有字段与显式默认值。`Reader` 不持有写句柄，也不提供写入接口。 |

22 个合成案例由 Go 与 Rust 对照测试共享，覆盖 branch、重复 ID、缺失 parent、metadata leaf、多次/离 branch compaction、丰富消息、错类型 optional 字段、Unicode 与大整数等。成功及 header 失败读取核对 bytes 和 mtime 不变。唯一归一化为 Rust `f64` 与 Go 精确 JSON 数字的等值拼写（如 `0` 与 `0.0`）；ID、时间、字段、错误类别和数组顺序不归一化。

新增对照测试最初因 Rust expected cost 的 `0` 与实际 `0.0` 比较失败。只调整本次测试比较器后通过，未修改旧业务断言。Go 保留了 Rust 无 cycle 检测的行为，不为损坏关联树新增截断或降级策略。

## 验收结果与边界

- Go session/transport、共享 fixture 的 Rust reader 对照、原有 restore 测试均通过；只读 bytes/mtime 检查通过。
- Linux/Windows 实际运行未验证；Electron 历史呈现和原生 GUI 由 T003 负责。
- 本项不实现 JSONL 创建、append、rename、delete、cwd 改写、写后索引更新或实际 compaction；也不代表 SPEC 全部 JSONL/逻辑验收完成。
- 未做系统级 I/O 故障注入、真实会话/凭据验证或全项目 TEST。
