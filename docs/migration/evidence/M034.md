# M034 — GitHub Copilot OAuth

## Behavior implemented

- `internal/model/oauth/copilot.NewClient(*http.Client)` provides an injectable HTTP client and configurable GitHub/API endpoints.
- `Client.Login` requests a device code, emits typed prompt/device-code/wait/progress events without emitting device or access tokens, polls RFC 8628 pending/slow_down results, then exchanges the GitHub token for a Copilot token.
- Device expiry, provider denial, cancellation, malformed responses, and HTTP failures return explicit errors. Model enable requests retain the Rust behavior: post the known model policy updates best-effort and do not interpret success as entitlement.
- Enterprise host information is normalized and saved in `enterpriseUrl`; refresh uses that host and preserves the stored GitHub token and all extra credential fields.
- `app/auth.Copilot` stores, refreshes, and removes only `github-copilot` at the caller-supplied auth path and invokes the injected `func(context.Context, string) error` model-change callback for that provider after successful login/refresh/logout.

## Source comparison

Compared with `crates/rozsa-model/src/oauth/github_copilot.rs`, `crates/rozsa-model/src/oauth/device_code.rs`, and `crates/rozsa-model/src/credentials.rs` (`refresh_github_copilot_oauth`): device-code endpoints and fields, GitHub token exchange, Copilot token expiry skew, `enterpriseUrl`, device outcomes, best-effort model policy updates, and refresh metadata behavior are represented in Go. HTTP errors avoid returning response bodies that could contain credentials.
