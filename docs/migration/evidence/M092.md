# M092 — Shared model availability and refresh

Model metadata is loaded from `<global>/models/` then `<project>/models/`, with
project entries taking precedence. Main and small models use the same catalog;
`<global>/models/auth.json` is the canonical credential file for desktop and CLI.
The catalog preserves Rust's Anthropic/Codex/Copilot auth filtering, Codex account
requirement, and other providers' configured key/environment resolution.

Listing may renew and persist OAuth credentials. Registered dynamic discovery
updates only its provider; the production registration is Codex `/wham/models`.
Anthropic and Copilot recompute availability after login/refresh/logout without
inventing a remote catalog endpoint. Static providers are never queried for a
model list. Project overrides and other providers survive dynamic writes.
Runtime requests resolve current credentials, including Codex account headers,
so a previously selected model observes token rotation and logout.

Typed RPC/main/preload APIs expose login, manual response, next event, cancel and
logout. The existing `/login <provider>` and `/logout <provider>` desktop command
path uses these APIs. Main opens trusted authorization URLs through the OS;
navigation cancels pending authorization and discards late browser events.
Directory metadata is checked each second; unchanged state emits nothing.
Renewal/discovery checks run at most once per minute while unchanged; Codex's
remote catalog retains its 24-hour cache. Model updates replace both selectors
without silently changing the persisted selection. Refresh/read failures remain
visible as diagnostics and enter the existing desktop exception path; directory
read failures can recover. Startup reports an unavailable selected provider.
