# M062 — Keyboard shortcut Go contract

## Source comparison

The Go registry and persistence behavior were compared with:

- `crates/rozsa-gui/src/key_bindings.rs`
- `crates/rozsa-gui/tests/key_bindings.rs`
- `crates/rozsa-gui/frontend/app.js` (`FIXED_KEY_BINDINGS`)

The port defines the same seven editable actions and six ordered fixed entries,
including titles, descriptions, defaults and scopes. It reads the version 1
global `key_bindings.json` override file,
inherits built-in bindings for missing overrides, and persists only customized
bindings. Update/reset return the effective ordered registry. Modifier spellings,
special key names, duplicate-modifier rejection, case-insensitive collisions,
and the Rust function-key prefix rule follow the source implementation. Fixed
shortcuts and Electron native accelerators remain outside this Go contract; the
renderer/native capture flow belongs to T047.

## Verification

Command: `go -C backend test ./internal/app/keybindings/...`

Result: PASS on the current macOS host. Dedicated Go tests cover defaults and
inheritance without file creation, definitions and scopes, global config path,
override-only persistence, reset recovery, malformed/version/unknown-action/
trailing-value files, duplicate persisted shortcuts, case-insensitive conflict,
invalid binding rejection without state changes, supported modifiers and key
names including F11, and write failure propagation.

An earlier run of the same command failed because the test fixture used a
lowercase modifier (which the Rust validator rejects) and modeled an uncreatable
parent as a read failure. The fixture was corrected to use a valid modifier with
a case-only key collision, and missing-path detection was aligned with Rust's
`Path::exists()` behavior. The final run passed.

The API is synchronous and has no cancellation input or cancellation state;
cancellation is not applicable to this module and was not tested. Recovery is
verified by resetting a persisted override and observing the built-in default
and an override-free file. No Linux or Windows runtime verification was done.
