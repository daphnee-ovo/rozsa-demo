# M010：当前 RPC 类型、错误与取消契约

进入日期：2026-10-15，Asia/Singapore。对应 TASK-T010、SPEC-AC-003/007/015。

## 已批准的协议边界

用户明确禁止手动实现 JSON-RPC 2；Go 使用 `go.lsp.dev/jsonrpc2` 原生 Conn/Stream，Electron main 使用 `vscode-jsonrpc` 原生连接/framing/ID handling。产品只使用库公开支持的配置；若需求仍不支持，回主会话重新决策，不加自定义 Stream、framing 或额外解析器。依赖版本以各自 manifest/lock 为准。

库负责 framing、envelope 与 transport ID。业务方法、参数类型、领域错误、身份路由、事件 epoch/watermark 仍由产品定义。已实现方法为 initialize、get_sessions、switch_session、shutdown；后续方法由对应切片增量添加。

| 情形 | 约定 |
| --- | --- |
| 参数 | 方法允许空参数时，missing 与 null 等价；必填 version/path/catalogId 仍校验。 |
| Notification | 缺失/null transport ID 按 notification 处理且不回复；当前没有声明可由 notification 调用的产品方法。 |
| malformed JSON / 非法 envelope | 库返回解析/请求诊断并终止连接；不补发 wire error response。合法 envelope 中的业务参数错误返回 typed RPC error。 |
| 错误映射 | catalog/session、not_initialized、closing 使用领域错误；未知错误 kind、malformed 结果或 identity mismatch 透明失败，不伪造空成功。 |
| 关闭 | shutdown 响应后拒绝新产品请求；main 结束 stdin，由库 drain pending work，再等待其拥有的 Go 进程退出。 |

## 取消、失败与身份

ProductClient 的 AbortSignal 只拒绝 UI 等待。已发请求继续由 Node 库接收并关联，不跨 IPC 发送 AbortSignal 或产品 abort；迟到 success/error 会被消费，session history 另以 revision 阻止旧结果覆盖新选择。timeout、断管和退出转为 typed transport failure，pending 请求失败，不重发、不自动重启。有副作用请求不能自动重试。

transport ID 不替代 `target.path`、`catalogId`（JSONL header ID）、`sessionId`（filename stem）或 `entryId`。当前候选只有只读列表和 Loaded history，没有 agent/tool/approval 的产品 abort 方法；shared fixture 对该方法应返回 MethodNotFound，不宣称实现了工作取消。

共享 session-RPC fixture 由 Go 与真实 Go 子进程/Node 库测试消费。首次回归发现响应缺少 `error.data.kind`，修复后当前实现通过；按批准的 malformed/null/notification 契约更新 fixture 时保留 typed 领域错误断言，没有借改断言掩盖实现失败。

## 验收边界

- 当前 Go/TS RPC 契约测试及列表/历史切片聚焦检查通过。
- 未验证最大 payload 吞吐、Linux/Windows 实机、事件并发同步、完整 agent/tool/approval 取消、native GUI 或全项目 TEST。
- 并发/snapshot 事件与异常退出/reload 生命周期分别由后续任务负责。
