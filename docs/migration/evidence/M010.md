## 已核对的库能力与差异

通过 `go list -m -versions go.lsp.dev/jsonrpc2` 查询版本，并通过
`go mod download -json go.lsp.dev/jsonrpc2@v1.0.1` 下载源码检查。
来源：[v1.0.1](https://github.com/go-language-server/jsonrpc2/tree/v1.0.1)，
commit `285c360f07498d9f27aeb3b6e342cd5de86ac748`。已精确加入 backend/go.mod
及 go.sum。Go 的 `NewConn(NewStream(...))` 拥有协议及 framing；stdio 类型仅适配
Reader/Writer/Close，不实现 Stream。Electron main 使用
[`vscode-jsonrpc@9.0.3`](https://www.npmjs.com/package/vscode-jsonrpc/v/9.0.3)
的 `createMessageConnection`、`StreamMessageReader`、`StreamMessageWriter`，
删除旧手写客户端 framing 与 pending ID map。

| 项目 | 旧候选/测试 | 本项批准并实现的契约 | 验证 |
| --- | --- | --- | --- |
| body/header 限制 | 64 MiB / 8192 bytes | 采用 Go 库的 1 GiB body 上限，不另设 8 KiB header 限制 | 超限 header 值直接拒绝，不分配 1 GiB；未做最大体积负载测试 |
| header 规则 | 拒绝重复 Content-Length 及 LF | 接受库的 LF 与重复长度后值覆盖行为 | Go library framing 测试 |
| missing/null params | 空参数方法允许 missing，拒绝 null | 两者均无参数；必填 version/path/catalogId 继续校验 | 共享 fixture |
| transport ID | missing/null 视为非法 request | 识别为 notification，不响应；当前没有声明接受 notification 的产品方法 | 无响应且不能初始化/关闭/执行产品方法 |
| malformed JSON/非法 envelope | 错误 response 后继续读取 | 库返回 ParseError/InvalidRequest 诊断并终止连接；不发送补偿 response | fixture 的 terminationCode 单列，与 wire error 分开 |

已检查 `Option` 及公开 `With*` 定义：`WithCodec`、`WithPreempter`。
这两项不提供上述 framing 限制或 null 保留设置。自定义 Framer/Stream 是扩展接口，
不等于这些行为已有配置项；依用户要求不使用它自行实现协议。

## 类型与业务路由

Go `internal/transport/types/session.go` 仅定义已实现的
initialize/get_sessions/switch_session/shutdown 方法、payload tags 与业务错误。
`contracts/ipc/session.ts` 提供方法/结果映射、request union、RemoteFault、
TransportFault、ProductFault；不定义或手写协议 envelope。后续方法随所属切片添加。

领域错误为 `catalog/session`（-32001）、`not_initialized`（-32002）、
`closing`（-32003）；参数与未知方法沿用标准错误码。handler 写入 `error.data.kind`，
main 经过 `RPCFailure`/`bridgeFault` 返回可序列化 union；preload/renderer 校验
code-kind 配对及错误 owner，ProductFailure 保留类型和 message。错误类型未知、
缺少产品 kind、结果 malformed 或 identity 不匹配透明失败，不返回空成功结果。

transport ID 由库关联并原样返回；不替代 target.path、catalogId（JSONL header ID）、
sessionId（file stem）或 entryId。关闭 handshake 返回 true 后拒绝新的产品调用，
main 再结束 stdin，库在 EOF 后 drain，main 等待进程退出。

## 取消与中断

对照 `crates/rozsa-gui/frontend/ui/scripts/core/ports.js` 和
`crates/rozsa-gui/src/commands.rs::abort`，保留 UI 接收取消与产品工作取消的区别。
ProductClient 的 AbortSignal 只拒绝 UI 等待；已发请求仍由 Node 库接收、关联和处理，
不跨 IPC 发送 AbortSignal 或产品 abort。预先取消及同一 tick 取消不会发起请求；
迟到 success/error 被消费，不污染后续调用。历史切换取消旧接收，并保留 revision 检查。

超时、断管及退出进入 typed transport failure，库拒绝 pending requests；无重发或
自动重启。测试用库实现的 synthetic endpoint 验证 timeout、退出、错误缺 kind 三种
故障只执行一次请求。等待 synthetic ready 后测请求超时，避免把端点启动算成被测请求；
生产请求超时默认仍为 10 秒。关闭测试均等待退出，检查 owned PID 不再存在。

当前仍只有只读列表与 Loaded history，没有 agent/tool/approval 的产品 abort 方法。
shared fixture 的 abort 返回 MethodNotFound；本项不假装实现实际工作取消。
