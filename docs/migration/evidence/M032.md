# M032 — Anthropic OAuth lifecycle

## Implemented behavior

- `internal/model/oauth/anthropic` builds the Anthropic authorization URL with
  PKCE S256, accepts a loopback callback or typed manual authorization input,
  exchanges the code, refreshes credentials, and observes request cancellation.
- Token endpoints and callback binding are configurable for local HTTP tests;
  empty configuration uses the Rust-referenced Anthropic endpoints and
  `127.0.0.1:53692` callback.
- OAuth flow events expose authorization URL and progress only. Token responses
  are returned to the app adapter and are not included in events or provider
  error bodies.
- `internal/app/auth.Anthropic` takes an explicit auth file path, stores and
  removes only the Anthropic credential through the shared credentials package,
  and invokes the injected model-change callback with provider `anthropic`.
  Starting a newer login/refresh or logging out cancels/supersedes the prior
  operation; a stale response cannot replace the current credential.

## Focused verification

```text
go -C backend test -count=1 ./internal/model/oauth/anthropic/... ./internal/app/auth/...
PASS
```

The local HTTP tests check the authorization-code and refresh request bodies,
PKCE URL fields, refresh-token retention, state rejection, context cancellation,
error-body token non-disclosure, stale-login persistence ordering, provider
isolation, and logout behavior. No real account authorization was performed;
that remains TASK-T054. Production construction now supplies
`<global>/models/auth.json` and the shared provider-scoped model-change callback.
The typed login controller, desktop browser request, model updates and exception
notification integration are covered by [M092](M092.md).
