## 🔴 P0 问题

### 1. 权限系统是死代码（安全假象）

**文件**：`crates/rozsa-app/src/permissions/mod.rs`、`crates/rozsa-tui/src/backend/native.rs:1312`

`permissions/mod.rs` 全文仅有一行占位注释：

```
// TODO: PermissionGuard, PermissionMode, risk analysis
```

- `PermissionGuard::evaluate()` 从未被 agent loop 或 NativeBackend 调用
- `NativeBackend::respond_permission()` 直接 `return Ok(())`，用户的 approve / reject 操作被静默丢弃
- Settings 里已有 `permissions.mode` 和 `auto_approve_patterns` 配置项，但无任何运行时代码消费它们

**用户感知**：TUI 渲染了权限确认 UI，用户以为选择了 reject 就阻止了危险操作，实际上工具无条件执行。对 `bash rm -rf ...` 类命令无任何守卫。

**修复方向**：在 `agent_loop` 的 `pre_tool_use` hook 处调用 `PermissionGuard::evaluate()`；`respond_permission` 真正解析 UI 回应。见 [NATIVE_TUI_GAP_AUDIT.md §2.1](NATIVE_TUI_GAP_AUDIT.md) 阶段 C。

---

### 2. `/compact` 及约 12 个 slash 命令静默无效

**文件**：`crates/rozsa-tui/src/backend/native.rs:1327`、`crates/rozsa-app/src/slash_commands.rs`

TUI 自动补全展示 29 个 slash 命令，以下命令执行后**静默失败或被转发给 agent 当成自然语言处理**：

| 命令 | 现状 |
|------|------|
| `/compact` | `NativeBackend::compact()` 返回通知文字，不执行压缩 |
| `/export` | 无实现 |
| `/import` | 无实现 |
| `/share` | 无 GitHub gist 逻辑 |
| `/copy` | 无剪贴板操作 |
| `/fork` `/clone` `/tree` `/graph` | session 分支逻辑未实现 |
| `/login` `/logout` | OAuth 未对接 TUI |
| `/permissions` | 权限系统本身未接入 |
| `/search` | 工具输出搜索未实现 |
| `/gc` | session 清理未实现 |
| `/lsp` | LSP 配置持久化缺失 |

**用户感知**：输入命令后无任何反应，或 agent 开始用自然语言猜测命令意图，严重损害信任感。

**修复方向（最低成本）**：对未实现的命令在执行时返回 "该命令尚未实现" 提示，而非静默。

---

### 3. 上下文压缩（compaction）引擎已实现但链路断开

**文件**：`crates/rozsa-app/src/compaction/mod.rs`、`crates/rozsa-app/src/agent_session.rs:379`

`CompactionEngine`（136 行，含 `prepare_plan` / `replace` 完整逻辑）已实现，但：

- `agent_session.rs:397` 仅用 `should_stop_for_compaction()` 在到阈值时**停止 agent loop**，不压缩后继续
- `CompactionEngine::prepare` / `replace` 从未被调用

**用户感知**：长会话中 agent 突然停止响应，也无法通过 `/compact` 手动触发，上下文窗口满了就只能新开会话。

## 🟡 P1 问题

### 4. 侧边栏 Token 统计恒显 0

**文件**：`crates/rozsa-tui/src/backend/native.rs:185`（`push_state_with`）

`stats` 和 `context_usage` 字段写死为 `None`，导致：

- TOKENS 面板显示 `0 / 0`（In / Out 恒 0）
- CONTEXT 进度条恒为空

`AssistantMessage.usage.total_tokens` 和 `Model.context_window` 数据均已存在，只需在 `push_state_with` 中累加读取。

---

### 5. 侧边栏权限模式、编辑模式、git 状态全部无数据

**文件**：`crates/rozsa-app/src/runtime_state.rs`

该文件仅有一行：

```
// TODO: RuntimeState snapshot for TUI consumption
```

`state.runtime_state: None` 导致侧边栏显示的权限模式、editMode、git 状态、活跃子 agent 均为 UI 默认值，而非真实运行状态。用户无法通过侧边栏判断 agent 当前的实际配置。

---

### 6. 标题栏会话名缺失

**文件**：`crates/rozsa-tui/src/backend/native.rs:185`

`session_name` 字段写死为 `None`。`SessionManager::current_name()` 已实现，接线成本极低（一行）。

---

### 7. Ctrl+Z 挂起后终端状态损坏

**文件**：`crates/rozsa-tui/src/app.rs`

只有基础 SIGTSTP 处理，缺少正确离开 alt-screen、恢复终端模式的逻辑。用户挂起后 `fg` 恢复进程，终端显示异常（乱码、光标错位）。

---

### 8. `--print` / `-p` 命令行参数声明但完全无效

**文件**：`crates/rozsa-cli/src/args.rs:14-15`

clap 中声明了 `--print` flag，但 `run.rs` 从未读取此字段。用户传入 `-p` 不报错也无效果。

---

### 9. 选择未实现的 LLM Provider 会 panic

**文件**：`crates/rozsa-model/src/types.rs`

以下 Provider 在枚举中已定义但无实现文件：

| Provider | 状态 |
|----------|------|
| `GoogleGenerativeAI` | ❌ 无实现 |
| `GoogleVertex` | ❌ 无实现 |
| `MistralConversations` | ❌ 无实现 |
| `OpenAIResponses` | ❌ 无实现 |

用户在模型选择器中选到上述 provider 对应的模型后，进程直接 panic，而非友好报错。

## 🟠 P2 问题

### 10. 工具调用时间戳恒为 0，进度事件从不 emit

**文件**：`crates/rozsa-core/src/tool.rs:15`、`crates/rozsa-core/src/agent_loop.rs:681`、`crates/rozsa-core/src/events.rs:36-41`

- `ToolResult.details` 始终为 `Value::Null`（字段从未赋值）
- `ToolResultMessage.timestamp` 始终为 `0`
- `ToolExecutionUpdate` 事件已定义，但 agent loop 从不 emit，TUI 无法显示工具执行进度

---

### 11. Token 计数使用 `chars/4` 粗糙估算

**文件**：`rozsa-model` 全局（无本地 tokenizer）

compaction 阈值判断以字符数除以 4 近似 token 数。对中文内容，实际 token/char 比约为 1:1（而非 1:4），导致压缩时机判断偏差可达 4 倍。

---

### 12. `rozsa-core::Agent` struct 无任何方法，对新贡献者造成认知歧义

**文件**：`crates/rozsa-core/src/agent.rs`

`Agent` 结构体有字段（model, tools, messages, queues），但整个 crate 无 `impl Agent` 块。实际执行逻辑在 `agent_loop.rs` 函数式风格中实现，`Agent` 是纯死数据。新开发者查看 `agent.rs` 会误以为找到了核心入口，实为误导。

---

### 13. 三套独立 Bridge 协议无法复用

**文件**：`crates/rozsa-core/src/protocol.rs`、`crates/rozsa-model/src/protocol.rs`、`crates/rozsa-app/src/main.rs`

三个 crate 各自定义 `BridgeInput` / `BridgeOutput` 并独立运行 stdin/stdout loop，无共用 trait。协议演进时需同步修改三处，维护成本是统一方案的三倍。

## 修复优先级汇总

| 优先级 | 项目 | 成本估计 | 理由 |
|--------|------|----------|------|
| P0 | 接入 PermissionGuard | L（SPEC 级） | 安全底线，缺失产生安全假象 |
| P0 | 未实现 slash 命令返回提示 | S | 成本极低，立即消除信任损伤 |
| P0 | 接通 CompactionEngine | M | 引擎已有，仅需接线 |
| P1 | `push_state_with` 只读字段补全 | S | 数据源均已存在，一次改动解锁 4 个面板 |

| P1 | 修复 Ctrl+Z 终端恢复 | M | 基础终端体验 |
| P1 | 删除或实现 `--print` flag | S | 接口诚实性 |
| P1 | 未实现 Provider 友好报错 | S | 防止 panic |
| P2 | 统一三套 Bridge 协议 | L | 降低长期维护成本 |
| P2 | 引入精确 tokenizer | M | 提高 compaction 时机精准度 |
